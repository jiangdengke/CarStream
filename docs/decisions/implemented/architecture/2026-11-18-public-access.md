# Agent Note: 公网入口使用私有反向隧道和独立 TURN

Status: implemented

## Problem

用户要求通过阿里云指定端口访问板端直播，并确认独立反代、必要的 TURN 和强令牌。
板端没有公网入站入口；HTTP 代理只能转发网页与信令，不能替代媒体连通性。
云端已有两套 Nginx，系统为 Ubuntu 18.04，不能覆盖现有代理或依赖老旧系统包部署新公网服务。

## Decision

网页入口使用独立 Nginx 容器的 HTTPS 7777，经云端回环 17777 和板端主动 SSH 反向隧道到板端回环 8080。
当前后端是替换板 `linaro@192.168.50.84` 的 `/home/linaro/magnet_car_project/cam`，复用已有云端代理、证书和 TURN。迁移替换旧板的专用公钥，保留原条目的强制命令与转发限制；旧板恢复后也不能争用同一入口。新板已有强令牌保持不变，并同步到云端私有配置，旧云端令牌失效。保留新板原分辨率和新版插件/MPP，不复制旧板低带宽档位。
板端新增专用 Ed25519 密钥，私钥不离开板子；云端使用无交互 shell 的独立账号，固定 SSH 主机公钥。
隧道使用用户级 systemd 自动重连并开启 linger，Python 应用继续由根目录启停脚本手动管理，不因本决定自动开机。
旧 OpenSSH 不支持每密钥 permitlisten，现有 GatewayPorts 保持不变；客户端只请求回环监听，但不声称服务端已限制密钥只能建立这一条转发。

云端未提供域名，入口使用带 IP SAN 的 90 天自签证书；先核验指纹再信任，正式分发应换受信任证书。证书不自动续期。
随机网页令牌与 TURN 密码独立生成，关闭弱令牌开关并固定精确 HTTPS Origin。旧 localhost 页面不再具有合法来源。
公网路由由 backend-ready 文件控制，启用前必须验证新进程已拒绝旧令牌和错误来源，并接受强令牌。

TURN 使用独立 Coturn 容器、静态长期凭据和私网/回环/组播 peer 禁止规则。
公网 UDP 探测超时，但 TCP 3478 在板端和外网可达；因此配置显式 transport=tcp 并强制双方 relay。
配置层只接受空查询、transport=tcp 或 transport=udp，浏览器 URI 保留查询，turns 不允许 UDP。
中继内部仍使用 UDP 端点，客户端到 TURN 使用 TCP，不承诺所有流量只经过 7777。
容器固定镜像摘要、非 root、只读文件系统和资源/日志限制；只给 Coturn 上游文件能力所需的 NET_BIND_SERVICE。
默认路由、摄像头网络、现有 Nginx 和 Docker 守护配置保持不变。初次部署不修改 SSH 服务端配置；后续经单独授权的[专用隧道双向检测](../bug-fix/2026-11-18-tunnel-server-heartbeat.md)仅补充该账号的失活检测，不改变其他用户有效配置。Firewalld 只增两条必要 UDP 端口的运行与永久规则，不全局 reload。

部署配置见 deploy/cloud 与 deploy/board；具体凭据路径、指纹、回滚和验收见[部署记录](../../../deployment.md#public-access-through-alibaba-cloud)。
本决定补充[媒体边界](2026-11-17-python-gstreamer.md)与[手动启停](../process/2026-11-17-service-scripts.md)，不改变独立观看管线和同步脚本的被动部署规则。

## Alternatives considered

- 直接公开 SSH 反向端口最简单，但会绕过独立 HTTPS 和入口限制，也容易把私有弱令牌调试配置公开，因此只转发到云端回环地址。
- 复用既有 Nginx 无需新实例，但云端有多套自定义服务和老版本二进制；独立容器避免修改现有配置，并使用较新的组件。
- 系统 apt 包易于管理，但此主机提供的 Coturn 版本较老；采用上游容器并固定摘要，不升级整台主机。
- UDP TURN 通常更适合实时媒体，但实际公网探测超时；可达的 TCP 中继提供当前可验证路径，接受队头阻塞与时延代价。
- 域名与公开信任证书更适合正式服务，但用户未提供域名；采用明确标记的临时自签证书，不改为明文传输令牌。

## Consequences

收益是网页与媒体均可从公网独立到达，不要求观看者加入 Tailscale；代价是云端带宽、额外运维、静态凭据轮换及自签信任/续期工作。
共享令牌不是用户账号体系，当前没有按用户带宽配额或完整滥用防护。老旧云主机、内核、Docker 和宽 TCP 防火墙仍是维护风险，容器不能消除。
TURN 公网鉴权分配和中继互发数据通过；强制 relay 的原生公网客户端在 60 秒内解码真实 2304x1296 视频 992 帧。
替换板公网检查在 60 秒内解码 1241 帧原分辨率真实视频，无重连，但最长解码帧间隔为 2.458 秒，因此两秒连续性目标仍未通过。迁移只确认公网接入，不把更换板子或隧道身份当成卡顿修复；未降低画质或放宽验收阈值。新板隧道 enabled、active、Linger=yes，重启隧道后健康恢复；应用仍不自动开机。备份、验证和回滚见[新板公网切换](../../../deployment.md#replacement-board-public-cutover-2026-11-19)。
客户端最初只有 ECDSA DTLS 密码套件而握手失败，临时客户端增加浏览器常用 RSA 套件后通过；没有修改生产媒体代码或跳过证书指纹校验。
浏览器、长时间稳定性、并发容量、自动断线恢复和重启主机仍未验收；本次短测不证明历史停帧根因已修复。
回滚必须先关闭公网路由并停隧道，再恢复包含弱令牌的旧板端配置，不能直接把旧配置重新公开。
