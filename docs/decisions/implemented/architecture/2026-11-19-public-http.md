# Agent Note: 用户确认后将专用公网入口改为 HTTP

Status: implemented

## Problem

用户放弃域名与 HTTPS，要求使用公网 IP 加端口观看。原自签证书阻断 Cursor 浏览器；域名签发另遇到备案拦截。不能把接收视频与本机摄像头权限混为一谈，也不能未说明风险就降低公网保护。

## Decision

仅将独立项目代理的 7777 改为 HTTP，并把板端与云端私有配置的精确 Origin 同步为 `http://8.130.208.68:7777`。用户已明确接受访问令牌、TURN 凭据及信令明文传输与中间人篡改风险。保留强令牌、鉴权先于媒体、同源校验、路由白名单、限流、发布门、独立 TURN 和 SSH 隧道。

不改其他 443 业务，不添加域名入口，不修改浏览器安全开关，不降低画质。旧证书保留用于回滚，不自动删除私有备份。更换 Origin 通过现有启停脚本重启本应用。

## Alternatives considered

- 保留 IP HTTPS 可保护令牌与信令，但用户明确拒绝继续使用 HTTPS，且现有自签证书没有获得 Cursor 信任。
- 域名加受信任证书能兼顾安全与无提示访问，但前轮公开验证返回阿里云备案拦截，用户明确放弃该路线。

## Testing

备份配置后关闭发布门，校验并重载 HTTP 代理，通过现有启停脚本重启本应用。新 HTTP 页面与健康检查通过，错误 Origin 返回 403，空令牌和错误令牌被拒绝，原令牌正常鉴权，随后恢复发布。用户源码哈希与画质设置保持不变，其他 443 配置与备份一致。

Cursor 在非安全 HTTP 上实际接收并呈现 2304x1296 真实摄像头画面，候选对为 relay/relay。90 秒观察中呈现 1658 帧、无会话变化；最大呈现回调间隔 5.6754 秒，因此两秒呈现连续性未通过。回调间隔不等同网络包间隔或单独证明摄像头停帧原因。不宣称原断流或卡顿问题已修复。详见[当前部署与回滚](../../../deployment.md#public-http-cutover-2026-11-19)。

## Consequences

HTTP 页面、共享令牌、TURN 凭据和信令可被监听或篡改。媒体 DTLS/SRTP 仍在使用，但不可信信令使其不能抵抗主动中间人。此方案不是与 HTTPS 等价的安全部署，也不承诺其他浏览器或长时间连续性。

收益是当前 IP 入口不再要求浏览器信任自签证书，Cursor 实际接收视频可用。代价是明确放弃公网页面与信令的 TLS 保护；保留令牌和来源校验不能补回这些保护。应用不增加本机摄像头权限或浏览器安全例外。

## Existing decision audit

检索全部 11 篇原有活跃笔记，原[公网入口决定](2026-11-18-public-access.md)的 HTTPS/Origin 部分被本决定部分替代；其私有隧道、独立 TURN、发布门与强令牌约束仍有效，不归档。媒体边界、播放器恢复与手动启停部分重叠但不改变；其余笔记与此次传输方式变更无关。没有需要删除或归档的提案。
