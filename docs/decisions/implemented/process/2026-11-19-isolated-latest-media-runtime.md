# Agent Note: 新板使用独立前缀的新版插件与配套 MPP

Status: implemented

## Problem

替换板子的系统 MPP 1.3.9 缺少新版 Rockchip 插件所需的 `MppSysCfg`。
前一轮使用匹配旧库的 2024 年插件完成合成验证，但用户明确要求使用新版，并确认仍是此前已提供配置的摄像头。
需要满足新版要求，同时不破坏板上其他程序使用的厂商库，也不能把测试彩条当作摄像头启动成功。

## Decision

使用当前上游版本并记录固定提交：MPP develop 为 `9b56348cc61393c84662e6d6dd78feae67773a36`，插件 gstreamer-rockchip 为 `bff0659a51c13585b3c9c9a68aa8c435beeb3fe1`。
两者一起编译到 `/home/linaro/.local/opt/carstream-media-latest-20261119`，只由该应用私有环境加载。
`PKG_CONFIG_PATH` 指向配套开发文件，插件链接时记录独立库路径，运行时使用 `GST_PLUGIN_PATH`、`LD_LIBRARY_PATH` 和独立 `GST_REGISTRY`。
以进程实际映射的库路径验证版本选择，而不是凭插件未变化的 1.14.4 标识判断。
系统 MPP、RGA、内核和上一轮兼容插件保持原状，现有按用户授权的设备 ACL 保留；本轮不增加系统软件包或全局库搜索配置。

摄像头配置取自用户已有 `inter_video.py`，只解析字符串，不导入或执行脚本。
原凭据通过 SSH stdin 进入板上私有 `.env`，与不含凭据的 RTSP 地址分开保存，不进入源码、文档或诊断输出。
网页强令牌、回环监听、原分辨率档位和摄像头本身设置保持不变；只启动当前 `cam` 部署。
本机私有 SSH 页面转发便于用户访问，不等同于迁移旧公网入口。

## Alternatives considered

- 匹配系统 MPP 的旧插件已经通过合成验证，依赖改动最少；但不满足本次明确的新版要求，保留为撤回点而不继续作为当前版本。
- 全局安装新版 MPP 能让工具默认发现新库；但会影响其他程序和板上厂商组件，因此选择应用独立前缀和显式加载。
- 直接沿用此前插件目录而只换库便于少改配置；但会混淆两个已验证组合，独立目录和 registry 能明确区分当前与回退版本。

## Consequences

收益是满足新版要求且不覆盖系统厂商栈；代价是启动环境必须同时保留三个原生路径变量，后续升级也须将插件与 MPP 配套验证。
源文件上传不包含 Git 元数据，所以 MPP 日志版本字符串为 unknown；固定源码提交与运行库路径是本次版本证据，不应误报为系统自带库。
旧 `.env` 保存在 `.latest-runtime-backup-20261119T022813Z/.env`，恢复该点会退回测试源和旧插件，而非继续提供真实摄像头。
只需停服务时使用 `./stop.sh`，不必删库、删除设备 ACL 或降级系统包。

硬件合成转码、27 项 Linux 测试、原生 WebRTC、同序号重传、SSRC 和十轮释放检查通过。
当前服务已使用旧摄像头凭据，原生客户端实际解码 2304x1296 画面；但一分钟检查未完成，最长已观察帧间隔为 4.244 秒，随后接收轨道结束。
因此交付边界是安装、真实源启动与初始出画，不是连续播放、浏览器、公网或端到端延迟验收。
服务保留运行，诊断接收端已关闭；本轮不扩展到暂停中的延迟或稳定性修复。
完整验证和撤回命令见[新版运行时部署记录](../../../deployment.md#latest-isolated-media-runtime-and-real-camera-startup)。
