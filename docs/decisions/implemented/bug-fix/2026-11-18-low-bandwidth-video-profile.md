# Agent Note: 低带宽链路显式选择硬件转码档位

Status: implemented

## Problem

启用原生重传后，原分辨率约 1.5 Mbps 视频仍有数秒停顿，随后公网试验连首帧也未能解出。板端独立 aioice 合成传输同样不能按目标速率及时交付，排除仅由摄像头或 GStreamer 编解码造成这一现象。
当时板端到公网 TURN 的 TCP 连接显示 delivery_rate 约 547 kbps、发送积压约 63 KB、累计重传约 210 KB。相同云端 TURN 的 Mac 本机双 relay 对照中，两种发送节奏各 1600 包全部到达。该证据支持当前板端路径吞吐不足，不足以定位运营商、路由器或具体丢包点。

## Decision

配置增加显式 VIDEO_PROFILE，默认 original 保留现有分辨率和约 1500 kbps 编码目标，不静默改变其他部署画质。
low-bandwidth 在 H.265 转码路径上使用现有 MPP 解码器硬件缩放为 1280x720，H.264 编码目标为 350 kbps，MPP CBR 范围 300-400 kbps；保持 GOP、Baseline、RTP 分包和 RTSP 参数不变。码率范围是编码器控制目标，不是每个瞬时网络窗口的硬上限。
测试源维持 640x360，只调整编码目标；H.264 摄像头透传不能改变码率与分辨率，因此配置验证明确拒绝该组合，不假称已经生效。该档位不是自动拥塞控制，也不包含运行中自动切换。

用户已确认优先稳定、接受清晰度降低，并授权隔离真实流连续播放检查通过后才修改生产私有配置。摄像头原始码流、默认路由、网卡、TURN 凭据和用户访问令牌不变；切回 original 可恢复此前应用画质，不需修改摄像头。

## Testing

配置测试检查默认值、环境选择、非法档位和 H.264 透传拒绝。隔离真实流必须确认实际解码 1280x720、连续至少 300 秒、平均解码至少每秒十帧，并要求启动后最大帧间隔不超过两秒；仅设置属性、HTTP 存活或进程退出成功均不够。
最终低带宽构建通过十次真实 TURN 候选分配后的严格释放检查，每次文件描述符为 17；原生可控丢包与 SSRC 回归通过。真实流结果、部署状态和回滚点见[低带宽部署记录](../../../deployment.md#low-bandwidth-video-profile)。

350 kbps 隔离真实流通过：300 秒解码 6031 帧，实际 1280x720，启动后最大帧间隔 1.556 秒。随后完整公网试验解码 4846 帧、持续 300 秒且没有重连，但最大帧间隔 2.183 秒，严格两秒门槛失败；不修改门槛来宣布通过。

板端独立传输的计数在限定接收窗口结束时仍有排队，不能把未及时收到的包全部当成永久丢包，第二轮又受到第一轮积压影响，不能将其当成严格独立的节奏对照。TCP 内核拥塞和交付速率证据独立保留。

## Alternatives considered

- 只增加[原生重传](2026-11-18-native-video-retransmission.md)能补包，但当前路径持续吞吐小于发送量时会增加额外流量，不能替代降低发送负载。
- 保留原分辨率、只设低码率改动更少，但在 2304x1296 下 350 kbps 的画质利用较差；已有 MPP 解码器支持硬件缩放，因此选择 720p 而不是新增软件缩放路径。
- 改摄像头主码流可减少输入，但会影响其他摄像头客户端且不是修复公网出口所必需；只在每位观看者的板端转码链路调整。
- 自动拥塞控制适应范围更广，但涉及反馈估计、运行中编码器重配置和新的状态机；本次采用用户认可的显式档位，不冒充已实现自适应。
- 更低的 200 kbps 隔离试验能进一步减少流量，但发生媒体、板端 SSH 和反向隧道同时不可达，无法形成有效画质或稳定性比较；未部署，移除临时码率覆盖项，不据此继续降低画质。

## Consequences

收益是当前有限出口下可减少长期积压，保留原画质回退开关与每位观看者独立管线。代价是清晰度降低、快速运动可能有压缩失真；350 kbps 加协议和 RTX 开销仍依赖实际可用带宽，不保证所有网络环境稳定。
本档位不会消除 RTSP 源故障、物理断网或多观看者带宽总量限制。不能以一次有限时长试验声称长期、浏览器或多人容量验收完成。
后续公网返回 502，云端反向监听不存在，板端 SSH 超时。当前是连接恢复阻断，不是继续猜测编码参数的依据；远程不可达本身也不能定位物理断网、供电或板端系统故障。须恢复访问后核实应用与诊断清理，再复测完整公网路径。
